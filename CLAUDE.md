# CLAUDE.md — Holocron

## What This App Is
Holocron is a personal, locally-hosted, single-user archival database for tracking Star Wars multimedia. Runs at localhost:5000. No authentication. No login screen. No external API calls at runtime. American releases are the primary focus.

## Tech Stack
- Backend: Python 3.13, Flask, Flask-SQLAlchemy, Flask-Migrate (Alembic)
- Database: SQLite — file: data/holocron.db
- Frontend: Jinja2 templates, Tailwind CSS v3 (devDependency in package.json)
- Interactivity: htmx (loaded globally), small amounts of inline JS where needed
- Rich text: Quill (Issue synopsis)
- Fuzzy search: rapidfuzz
- Package management: uv (Python), npm (JS/CSS)

## Tailwind CSS
Compile command (run from project root):
```
npx tailwindcss -i app/static/css/input.css -o app/static/css/output.css
```
- Uses Tailwind v3 — `package.json` devDependency, binary available via `npx tailwindcss`
- Config: `tailwind.config.js` — scans `app/templates/**/*.html`
- Input: `app/static/css/input.css` — Output: `app/static/css/output.css`
- Run after any template change that adds new Tailwind classes
- Note: Tailwind v4 has no usable CLI here — always use v3 (`npx tailwindcss@3` if initialising)

## Conventions
Established in Sprint 1:
- Flask app factory variable named `flask_app` (not `app`) inside `create_app()` to avoid collision with `import app.models`
- All models imported in `app/models/__init__.py` — required for Alembic autogenerate to detect tables
- `app/seeds.py::seed_all()` handles all startup seeding; checks table existence before querying (safe before migrations run)
- `log_contribution()` adds to session but does NOT commit — caller commits, keeping log + model change in one transaction
- `db.session.flush()` used before logging to get the new record's ID without committing
- Datetime values serialized to ISO strings via `_to_json_safe()` before storing in JSON log columns
- Slugs generated by `slugify()` in `app/utils.py`; uniqueness enforced by `make_unique_slug()` which appends `-2`, `-3` etc.

Established in Sprint 2:
- `seed_all()` uses `_row_count()` with raw SQL for table count checks — safe to call before migrations run
- SQLite + `batch_alter_table` requires named FK constraints — always name them (e.g. `'fk_persona_first_appearance_segment'`)
- `SeriesMembership` is intentionally FK-free on `series_id`/`entry_id` — polymorphic join, discriminated by `entry_type`

Established in Sprint 3:
- Floating-label pattern is used on ALL form fields site-wide: component classes in `app/static/css/input.css` (`fl-group`, `fl-label`, `fl-input`, `fl-select`, `fl-textarea`, `fl-static`, `fl-req`). Required fields use `<span class="fl-req">*</span>`.
- Segment blocks must NOT use `overflow-hidden` — it clips absolutely positioned autocomplete dropdowns; use `rounded-t-lg`/`rounded-b-lg` on header/body individually instead
- `<dialog>` element is used for modals; call `.showModal()` / `.close()`
- Tailwind arbitrary value `z-[9999]` is required for Story Breakdown dropdowns to float above all content
- Dates: display as "Oct 3, 2026" everywhere; cover dates display as month + year only ("Dec 2026"). Forms take numeric mm/dd/yyyy.
- UI label for issue-level credits is "Product Credits" (never "Container Credits" or "Issue Credits")
